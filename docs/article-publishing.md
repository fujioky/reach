# 自建文章发布

除了镜像（抓取 X / YouTube 内容，走 `/s/<token>` 私密分享链接），站点现在还能发布自己撰写的文章：Markdown 正文、上传图片与视频、公开固定链接、访客评论。

## 两条内容线的区别

|  | 镜像 | 文章 |
| --- | --- | --- |
| 来源 | 抓取自 X / YouTube | 自己撰写 |
| 访问 | `/s/<token>`，可限期 / 限次 / 阅后即焚 | `/p/<slug>`，公开、稳定、可被收录；归档页在 `/post` |
| 评论 | 平台原生评论，抓取后择优保留 | 访客提交，即时可见，后台可隐藏或删除 |
| 后台 | 「镜像」分组 | 「文章」分组 |

两者同住 `content_items` 表，用 `type` 区分（`'mirror'` / `'article'`）。文章独有的列都可空，历史镜像行不受影响：`slug`、`status`、`excerpt`、`cover_image_url`、`updated_at`、`comments_enabled`。镜像列表页用 `isNotArticle`（`lib/article/queries.ts`）过滤，注意它显式保留了 `type IS NULL` 的早期镜像行——`ne(type,'article')` 单独用会把它们一起丢掉。

## 写作流程

后台「文章 → 写文章」。编辑器左侧是 Markdown 源码，右侧是实时预览，预览用的就是公开页那个 `ArticleBody` 组件，所见即所得。

- **插入媒体**：工具栏的「插入素材」展开一个面板，分「上传 / 转存」和「素材库」两个标签页。前者把拖拽、选文件、粘贴远程链接汇成同一条队列；直接拖到正文区或往正文里粘贴文件也会自动展开这个面板并开始上传。封面图用的是同一个组件（限单张图片，且素材库只列图片）。插入的是 `/api/article-media/<mediaId>.<ext>` 这样的站内地址。
- **素材库**：已上传素材的缩略图网格，可搜索（文件名、所属文章）、按「未引用 / 图片 / 视频」筛选、多选后一次插入（角标显示点击顺序，正文里就按那个顺序排）。**范围是全站而不是当前文章**——它要解决的正是「某张图上传进了另一篇文章 / 那篇文章改写后不再引用它」这种情况：以前这类素材只能在「素材管理」里看见，插不回任何地方，重新上传又会多出一份副本，原件挂着等被清理。「未引用」筛选和缩略图角标就是为找出它们准备的。
  跨文章引用是安全的：媒体路由的访问判定只看「是否公开分享」和签名令牌，签名注入（`lib/article/media-url.ts`）也不限素材属于哪篇文章，所以一篇已发布文章可以正常显示上传在草稿里的素材。引用关系靠扫描正文得出，跨文章引用同样算「已引用」，不会被清理误伤。
  「素材管理」页里的上传面板不显示这个标签页——那个页面本身就是素材库。
- **队列逐项可见**：每个文件/链接一行，各自带状态、阶段和进度条，失败的留在列表里显示原因，可单独重试或一键重试全部，也可以把失败的链接一次性复制出来。此前只有一个「3/8」的总进度条，批量粘贴时失败提示会被下一条覆盖——作者最后拿到的是「一部分链接进来了」，却无从知道是哪几条。队列跑完若全部成功，面板自动收起；只要有失败就留在原地。
- **新文章的第一次上传**会自动先存一份草稿——媒体行要挂在文章 id 上，所以必须先有文章。作者不需要「先保存再上传」。
- **公开链接**留空时随机生成一串 10 位小写字母数字（`/p/552nl5w919`）。侧栏有「换一个」按钮，也可以手填——手填内容会先规范化（`My First Post` → `my-first-post`）再校验查重，而不是因为空格大写直接报错。已发布文章留空则保持原链接不变，避免外链失效。

- **封面版式**两种：「正文上方」是标题下方一张横幅；「标题背景」把封面铺在标题区，压一层从下往上加深的蒙版保证标题可读——文字压在底部，所以整体压暗只会白白让图变灰。
- **是否在归档展示**：公开链接下方的开关。取消勾选后文章不出现在 `/post` 列表，但 `/p/<slug>` 照常可读——适合只想定向发出去、不想摆在首页的文章。后台列表会标「不在归档」。

  最初的设计是按标题派生 slug，中文标题保留汉字。这个方案有个隐蔽的坑：中文 slug 必须在浏览器、路由、数据库之间的每一跳都正确地过一遍百分号编码，只要有一处没解码，文章就会在列表页正常显示、点进去 404（Next 交给页面的 `params` 就是未解码的）。随机 ASCII slug 从根上绕开了这一整类问题，而文章链接本来就是靠转发而不是手敲的。`/p/[slug]` 仍然会解码 params，让此前生成的中文链接继续可用。
- **发布时间**只在第一次发布时打戳，之后编辑再发布不会改写日期、不会打乱列表顺序。

## Markdown 支持

`react-markdown` + `remark-gfm`：标题、粗斜体、删除线、列表、任务列表、引用、行内代码与代码块、表格、链接、图片。

**不启用原始 HTML**（没有 `rehype-raw`）。正文存 Markdown、渲染 Markdown，注入面完全消失。代价是没有 HTML 逃生舱口——目前没有需要它的场景。

视频借用图片语法：`![说明](/api/article-media/<id>.mp4)`。Markdown 没有视频节点，渲染时也查不了数据库，所以用 URL 扩展名区分 `<img>` 和 `<video>`（`lib/article/markdown.ts` 的 `isVideoUrl`）。编辑器插入时会自动写对。

排版样式集中在 `app/globals.css` 的 `.article-prose`，跟随 Reach 的亮/暗色 token。

## 媒体存储

| | 后端 | 本地上传 |
| --- | --- | --- |
| 图片 | Vercel Blob（私有存储） | `@vercel/blob/client` 的 `upload()`，浏览器直传 |
| 视频 | S3 / R2（与镜像视频同一个桶） | 分块预签名 PUT（S3 multipart），浏览器直传 |

本地上传都**绕过 Route Handler**：Vercel 的请求体上限约 4.5MB，手机拍的照片和任何真实视频都过不去。

**视频上传是分块的**。直连 S3 端点的链路质量波动极大（吞吐会在一分钟内从 MB/s 塌到完全停滞），整文件单个 PUT 意味着一次抖动就全部重来。所以服务端开 multipart 上传并给每个 8MB 分块签一个 `UploadPart` URL（`createArticleVideoUpload`），浏览器 3 路并发上传、每块独立重试（4 次、指数退避、120s 停滞超时），全部完成后由 `registerArticleVideo` 在服务端 `ListParts` + `CompleteMultipartUpload` 合并成对象再登记——分块 ETag 由服务端收集，不依赖浏览器跨域读响应头。中途放弃则调 `abortArticleVideoUpload` 丢弃已传分块（R2 对未完成的 multipart 也会自行过期回收）。

上限：图片 20MB，视频 500MB（`lib/article/media.ts`）。

### 远程转存

「插入素材」面板下半部分可以粘贴远程图片/视频链接（每行一个，支持批量），封面图的面板同样支持。服务端抓取后存进本站存储，正文引用的仍是站内地址——**转存而非外链**，与镜像的思路一致：源站失效、防盗链、内容被替换都不影响已发布的文章。

类型**以响应头为准**，只有当响应头含糊（`application/octet-stream` 及同类，不少图床如此）时才回退到 URL 扩展名，最终仍要通过白名单。反过来不成立：响应头说 `text/html` 就当网页处理，哪怕 URL 以 `.mp4` 结尾——否则会把网页当视频存下来。

图片走内存缓冲后写入 Blob；视频直接流式接进 S3 multipart，不落内存——500MB 的视频塞不进函数内存。

**进度可见**：转存全在服务端进行，浏览器手里没有字节，所以进度只能由服务端讲。`POST /api/article-import` 用 NDJSON 流一行一个事件地播报「解析链接 / AI 解析 / 下载 x% / 转存 x% / 登记」，前端边读边更新那一行的进度条。Server Action 做不到这件事——它只能在结束时回答一次，这也是这条路由存在的唯一理由；`importRemoteMedia` action 仍在，内部调用同一个 `lib/article/remote-import.ts`。

流提前结束（函数超时）会被当成失败，不会当成成功——否则文章里会留下一个只转存了一半的文件。

**播放页自动跟进**：不少推特镜像 CDN 给出的 `https://host/AbC123.mp4` 其实是一张包着 `<video>` 的 HTML 页面，真正的文件在 `<source src>` 里。抓到 HTML 时会解析（限读 512KB），按顺序试三层：

1. **内嵌媒体地址**——`<source>` / `<video src>` / `og:video` / `<img src>`，以及脚本里以媒体扩展名结尾的带引号字符串
2. **页面级跳转**——`<meta http-equiv="refresh">`、`location.href = "…"`、`location.replace(…)`，以及 `location.href = destination` 这种先赋值给变量再跳的写法（广告中转页的标准长相）
3. **AI 解析引擎**——见下

最多跟进 4 层网页，走过的地址会去重防环，每一跳提取出的地址都重新走一遍完整的 SSRF 校验——它是远程页面里的内容，属于不可信输入。

### AI 解析引擎

内置规则覆盖的是**见过的**页面形态，而播放器把地址拆成三个变量、base64 编码、或者塞进混淆过的 bundle 时，每一种都要一条新正则，下一个站又换一套花样。所以规则用尽后，页面可以交给大模型再读一遍：「真正的文件在哪」。

- 在「系统设置 → AI 解析引擎」配置，**默认关闭**——把任意页面送进第三方接口是运营者的选择，不该因为一次导入失败就自动发生。OpenAI 兼容接口（Responses API），默认配的是火山方舟 `doubao-seed-evolving`。API Key 可以填在设置里，也可以留空改用环境变量 `AI_PARSER_API_KEY`。
- 只在规则失败后触发，每次导入最多两次。送出去的 HTML 先剔除样式、内联 SVG 和 base64，再截到约 48KB（保留首尾两端——播放器标签在顶部，填充它的脚本通常在底部）。
- 模型返回**候选列表**而不是单个地址，按可能性排序，逐个试到第一个真返回媒体的为止（`1080p` 挂了自动退到 `720p` 就是这么来的）。也可以返回 `nextPageUrl`，表示「这页只是跳转」。
- 模型的输出是不可信输入，和用户粘贴的链接同等对待：非 http(s) 直接丢弃，其余照样过 SSRF 校验，并且必须真的返回媒体类型才会被转存——**编造出来的地址在这一步就被挡掉，写不进文章**。
- 找不到时，模型对页面的判断（广告落地页 / 验证页 / 需要登录）会直接作为失败原因显示给作者，比「这是个网页」有用得多。

`lib/article/ai-resolver.ts` 只做这一件事，接口配置由调用方传入，因此 `remote-fetch.ts` 不需要依赖数据库。

**SSRF 防护**（`lib/article/remote-fetch.ts`）：这是全站唯一一处让用户提供的主机名进入服务端网络栈的地方，镜像那边用的平台白名单在这里不适用（任意图床都要能用）。因此：

- 只允许 http / https，挡掉 `file:`、`gopher:` 等
- 主机名解析出的**所有**地址都必须是公网地址——只要有一个落在私网、回环、链路本地（含 `169.254.169.254` 云元数据）、CGNAT、组播就整体拒绝
- 重定向手动逐跳跟随，每跳重新校验。让 fetch 自己跟随只会校验第一个 URL，而「公网域名 302 到元数据端点」正是标准绕过手法
- 转存视频时向 `downloadAndUploadVideo` 传 `disallowRedirects`，避免它重新打开最终 URL 时又被重定向到未经校验的主机
- 重定向次数、连接超时、字节上限都有约束；`Content-Length` 只作参考，真正拦住超大响应的是边读边计数

**未解决**：校验与建连之间的 DNS rebinding。彻底防住需要把连接钉到已校验的 IP 上，这在 fetch API 里没有自定义 dispatcher 就表达不了。该入口需要管理员会话，剩余风险的前提是攻击者已经拿到管理员权限——对他而言这不是有价值的攻击面。

正文里存的是 `/api/article-media/<mediaId>.<ext>`，不是存储地址——Blob 预签名 URL 一小时就过期，S3 对象又不公开，两者都不能写进文档。这条路由是**唯一**的媒体入口，访问控制和分发方式都在它里面决定，页面只管输出这一个地址。

### 访问控制：签名链接

| 素材状态 | 裸链接直接访问 | 文章页内 |
| --- | --- | --- |
| 已公开分享 | 可以 | 地址保持裸链接，可复制转发 |
| 未公开 | 404 | 地址带 `?t=<签名>`，6 小时有效 |

签名是 HMAC(`AUTH_SECRET`) 覆盖「media id + 过期时间」，服务端渲染文章时签发，路由验证后才放行。id 在签名内容里，所以一篇文章的令牌换不到另一个素材。管理员会话可以直接访问任何素材（草稿预览要靠它）。

刻意**不用 Referer** 判断来源：它可伪造、也常被剥掉，既不能可靠地放行也不能可靠地拦截。

签名过期返回 **403**（提示重新打开文章），伪造或缺失返回 **404**（不透露这个 id 是否存在）。

社交分享图是例外：爬虫来抓 `og:image` 时不可能带令牌，而分享卡片会被平台缓存很久，所以封面用 **30 天**的长效签名。封面本来就是文章的门面，这个取舍是合理的。

### 分发方式：代理还是直连

「系统设置 → 视频存储」里的**文章素材直连存储**开关（默认关闭），作用于同一条路由：

| | 关闭（代理） | 开启（直连） |
| --- | --- | --- |
| 视频 | 路由从 R2 读对象再流式吐出，**每个字节穿过 Vercel 函数** | 302 到 S3/R2 的**预签名 GET**，浏览器直接从存储取 |
| 图片 | 302 到 Blob 预签名地址 | 同左——Blob 只能这样读，两种模式没区别 |

主要节省在视频。

关于"私有"要说清楚：预签名只在 **S3 endpoint** 上才真正起门禁作用（不带签名访问 endpoint 返回 400）。而 **R2 一旦绑定自定义域，该域名下的对象就是公开的**——这正是 R2 文档里 public bucket 的形态，自定义域会完全忽略 SigV4 参数，无签名或乱签名都照样返回 206。所以配了自定义域时，直连 302 出去的目标是一个**永久公开**的地址，谁拿到谁能一直访问。

因此访问控制的边界在 `/api/article-media` 的签名令牌上，不在存储层。要让存储层也私有，得去掉自定义域（改用 endpoint + 预签名，但会失去自定义域的缓存策略），或在自定义域前加 Cloudflare Access。

开关只影响这条路由的行为，正文里存的地址始终不变，随时切换、无需迁移数据。

### 图片优化

正文图片和封面都走响应式：`/api/article-media/<id>.jpg?w=<宽度>` 返回按需缩放的 **WebP**，宽度取自固定档位（400 / 700 / 1000 / 1400 / 2000），渲染时用 `srcset` + `sizes` 让浏览器自己挑。实测手机视口取 `w=400`、桌面取 `w=1000`。

档位是固定的而不是任意宽度——开放的 `w` 参数等于让任何人往存储里塞无数一次性尺寸。不在档位上的值直接忽略，回退原图。

转换结果按 `articles/derived/<mediaId>-w<宽度>.webp` 缓存进 Blob，所以每个（图片 × 宽度）只转一次，之后每次请求都只是和原图一样的一次 302，函数不做任何事。缩放只缩不放：600px 的源图请求 1400 仍返回 600。

SVG 和 GIF 原样返回——前者是矢量，栅格化只会更大更糟；后者通常是动图，压成一张静帧比不优化更糟。

删除素材时会连同它的所有派生图一起清理，否则原图删了、派生图会永远留在存储里。

**首次请求不等转换**。请求路径只查缓存，查不到就立刻 302 到原图（`max-age=10`），转换用 `after()` 放到响应之后跑。一张 2MB 的照片转换要十几秒，让第一个读者干等只会等来一张破图——浏览器早就放弃了。等后台转完，下一次请求就切到 WebP。

### 视频封面帧

视频缩略图在**浏览器里**抓：上传时文件就在页面上，用 `<video>` 解码一帧、`<canvas>` 读出来，存成这个视频的 poster。服务端抽帧要 ffmpeg，而 serverless 函数里没有——打包一个进去要多 50MB，只为做浏览器已经会做的事。

远程转存的视频没有本地文件，就改成从存好的地址抓：浏览器只 range 请求文件头部就能解出一帧，不必下载整个视频。

抓帧刻意不取第 0 帧——很多编码的开头是黑场，缩略图会全黑，所以往后挪一点。整个过程是彻底的 best-effort 且不阻塞上传：浏览器解不了的编码就没有 poster，视频照常能用。

poster 存在 `media.meta.posterUrl`，通过 `/api/article-media/<id>.<ext>?poster=1` 读取。没有 poster 时该地址返回 404，浏览器当作「没设 poster」处理，与不写这个属性等效。素材管理里有 poster 就显示图片（一次小请求），没有则退回 `<video preload="metadata">` 让浏览器自己解。

### 素材管理

后台「文章 → 素材管理」（`/admin/articles/media`）列出所有文章素材，附总数、占用空间、未引用数量与可清理体积。

**引用统计**按文章正文与封面里出现的素材链接来算，而不是靠归属关系。原因是作者编辑的是自由文本：他可以删掉一张图、把同一个链接粘到第二篇文章、或在文章间搬运素材，这些都不经过任何能挂钩子的 API。文本是「这篇文章到底用了什么」的唯一真相。草稿里的引用同样算数。

因此列表里会出现「上传于 A 文，但被 B 文引用」这种情况，这是正常的。

**分享链接**是素材的站内地址 `/api/article-media/<id>.<ext>`。「公开分享」开关（存在 `media.meta.shared`）决定它对外是否可用：未公开的素材裸链接返回 404，只能通过文章页里那条带签名的地址访问；公开后链接对任何人长期有效，「复制链接」也才会真的复制。详见上文「访问控制：签名链接」。

**一键清理**删除所有无人引用的素材（数据库行 + Blob/R2 里的文件）。两道保护：

- **24 小时宽限期**——刚上传但还没存进正文的素材不参与批量清理。素材从「拖进编辑器」到「文章保存」之间一直是未引用状态，作者的草稿可能开着更久，只凭这个信号扫会删掉正在写的东西。这类素材在列表里标为「未引用 · 新上传」，需要立刻删可以用单条「删除」。
- **执行前重新扫描**——按钮按下时重新读一遍文章正文，页面渲染之后才被引用的素材会被放过。删除的依据是执行那一刻的真实引用状态，不是页面上显示的旧快照。

单条「删除」不受这两条约束：管理员看得见它在被引用，选择删除就是明确的意图。

### R2 / S3 需要开 CORS

视频直传要求存储桶允许来自站点域名的跨域 PUT，否则浏览器在请求发出前就拦掉了。Cloudflare R2 控制台 → 存储桶 → Settings → CORS Policy：

```json
[
  {
    "AllowedOrigins": ["https://你的域名"],
    "AllowedMethods": ["PUT", "GET"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["etag"],
    "MaxAgeSeconds": 3600
  }
]
```

本地开发再加一条 `http://localhost:3000`。没配的话上传会失败并提示「无法连接存储服务 — 请确认存储桶已允许本站域名的跨域 PUT（CORS）」。

视频存储参数复用「系统设置」里镜像视频那一套（`video_storage_*`）。没配置时视频上传会明确报错，图片上传不受影响。

## 访问密码

文章和镜像都可以加一道密码。每份内容独立选择三种模式之一：

| 模式 | 含义 |
| --- | --- |
| 不加密 | 默认，凭链接即可读 |
| 使用系统密码 | 跟随「系统设置 → 内容访问密码」里的统一密码，改一处全部生效 |
| 单独设置密码 | 只对这一份内容生效 |

存三种模式而不是直接存一个密码，是因为「跟随系统」和「用这个密码」随时间的行为不同：改系统密码时，跟随的内容应当一起变，如果保存时把密码复制进每份内容就做不到了。

**解锁范围按密码分组**：输对一个密码，所有使用同一个密码的内容都会解锁，有效期 7 天。实现上 cookie 里存的是对密码哈希的 HMAC，所以任何解析到同一个哈希的内容都认这份凭证，解析到别的哈希的则不认。哈希本身不出服务器，cookie 被拿走既看不出密码，也套不到用别的密码保护的内容上。

**未解锁时不泄露任何内容**：标题、摘要、封面、正文全在门后，页面 metadata 也只返回「需要密码」——那是爬虫和聊天软件链接预览会读的东西。归档页仍会列出条目（`listed` 管的是列不列），但只显示标题加一把锁，摘要位置写「此内容需要密码」。评论提交也会重新校验解锁状态，因为 Server Action 是个谁都能 POST 的端点。

**镜像上密码先于访问控制验证**。密码存在内容上，而有效期/限次/阅后即焚是单条分享链接的属性，所以同一份内容的多条链接共用一个密码。顺序很关键：`checkAccess` 才是消耗访问的动作，先跑它意味着任何人打开 URL、甚至乱猜密码都在花你的配额，还能在没看到内容的情况下烧掉一条阅后即焚链接。

> 实现这个功能时发现 `generateMetadata` 里调用的也是有副作用的 `checkAccess`，而 Next 每次请求都会执行它——于是阅后即焚链接在渲染页面之前就被 metadata 那一次消耗掉了，第一个访客只会看到「已失效」。现已改用只读的 `peekAccess`（`lib/access/control.ts`），它回答同样的问题但不改任何状态。

## 访客评论

评论**即时可见**，不排队等审核。挡住机器人的是三层，按代价从低到高：

1. **蜜罐字段** — 一个 CSS 藏起来、不在 tab 顺序里的输入框。填了就当提交成功，但不入库，不让机器人知道自己被识破。
2. **算术题** — 中文数字的加减法，答案和有效期用 `AUTH_SECRET` 做 HMAC 签名塞在 token 里。服务端不存任何状态，冷启动照样有效。改答案或改有效期都会让签名对不上。
3. **按 IP 限流** — 10 分钟内最多 5 条，两条之间至少 30 秒。直接查 `article_comments` 上的 `(ip_hash, created_at)` 索引，不用额外的计数存储，重启也不丢。

`ip_hash` 是 keyed HMAC 不是裸 SHA-256：IPv4 空间小到能穷举，裸摘要等于明文。这个值只跟自己比较，从不还原。

邮箱选填，存下来但从不显示。

后台在文章编辑页下方管理评论：隐藏（可恢复，留档）或删除（给不值得存的垃圾）。文章上的「允许访客评论」开关关掉后，新评论提交会被拒，已有评论仍然可见。
